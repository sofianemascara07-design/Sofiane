Use `GET /orders/{id}` to check the current status of a specific recharge order and retrieve delivery confirmation details once it completes.

## Endpoint

```
GET https://api.smartech-dz.com/v1/orders/{id}
```

## Authentication

All requests to this endpoint require a valid Bearer token. Include your API key in the `Authorization` header.

## Path Parameters

<ParamField path="id" type="string" required>
  The unique order ID returned in the `data.id` field of the `POST /orders` response (e.g. `ord_abc123`).
</ParamField>

## Request Example

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.smartech-dz.com/v1/orders/ord_abc123 \
  --header 'Authorization: Bearer sk_live_your_api_key'
```

```python Python
import requests

order_id = "ord_abc123"

response = requests.get(
    f"https://api.smartech-dz.com/v1/orders/{order_id}",
    headers={
        "Authorization": "Bearer sk_live_your_api_key",
    },
)

order = response.json()
print(order["data"]["status"])
print(order["data"]["delivery"]["confirmation_code"])
```

</CodeGroup>

## Response

A successful request returns **HTTP 200 OK** with the full order object, including delivery details when the order has completed.

```json
{
  "success": true,
  "data": {
    "id": "ord_abc123",
    "status": "completed",
    "product_id": "prod_ff_100",
    "denomination_id": "denom_ff_100",
    "player_id": "123456789",
    "reference": "order-003",
    "created_at": "2024-01-15T10:30:00Z",
    "updated_at": "2024-01-15T10:30:45Z",
    "delivery": {
      "delivered_at": "2024-01-15T10:30:45Z",
      "confirmation_code": "FF-XYZ-789"
    },
    "error_code": null
  },
  "requestId": "req_uvw456"
}
```

<ResponseField name="success" type="boolean">
  `true` when the order was found and returned successfully.
</ResponseField>

<ResponseField name="data" type="object">
  The full order object.

  <Expandable title="data fields">
    <ResponseField name="data.id" type="string">
      The unique Smartech order ID.
    </ResponseField>

    <ResponseField name="data.status" type="string">
      The current lifecycle status of the order. Possible values: `pending`, `processing`, `completed`, `failed`, `refunded`.
    </ResponseField>

    <ResponseField name="data.product_id" type="string">
      The product ID associated with this order.
    </ResponseField>

    <ResponseField name="data.denomination_id" type="string">
      The denomination ID associated with this order.
    </ResponseField>

    <ResponseField name="data.player_id" type="string">
      The in-game player UID targeted by this order. Present only for `PUBG_UC` and `FREE_FIRE_DIAMOND` orders.
    </ResponseField>

    <ResponseField name="data.reference" type="string">
      Your internal reference string provided at order creation.
    </ResponseField>

    <ResponseField name="data.created_at" type="string">
      ISO 8601 timestamp of when the order was created.
    </ResponseField>

    <ResponseField name="data.updated_at" type="string">
      ISO 8601 timestamp of the most recent status change.
    </ResponseField>

    <ResponseField name="data.delivery" type="object">
      Delivery details populated once the order reaches `completed` status. `null` while the order is still `pending` or `processing`.

      <Expandable title="delivery fields">
        <ResponseField name="data.delivery.delivered_at" type="string">
          ISO 8601 timestamp of when the recharge was successfully delivered to the player account or gift card.
        </ResponseField>

        <ResponseField name="data.delivery.confirmation_code" type="string">
          A unique delivery confirmation code issued by the fulfillment provider. Keep this for reconciliation and dispute resolution.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="data.error_code" type="string | null">
      If the order status is `failed`, this field contains a machine-readable error code describing the reason (e.g. `INVALID_PLAYER_ID`). `null` for all other statuses.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="requestId" type="string">
  A unique identifier for this API call, useful when contacting Smartech support.
</ResponseField>

## Error Responses

| HTTP Status | Error Code | Description |
|---|---|---|
| `404` | `ORDER_NOT_FOUND` | No order matching the provided ID exists under your API key. Verify the order ID and retry. |
| `401` | `INVALID_TOKEN` | The Bearer token is missing, malformed, or revoked. Check your API key and re-authenticate. |

<Tip>
  In production, prefer [webhooks](/concepts/callbacks) over polling `GET /orders/{id}`. Configure a `callback_url` when creating an order, and Smartech will push a status update to your endpoint the moment delivery completes or fails — eliminating unnecessary requests and reducing latency.
</Tip>
