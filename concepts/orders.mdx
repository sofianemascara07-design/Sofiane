An order represents a single recharge request submitted through the Smartech Recharge API. Understanding the order lifecycle helps you build reliable integrations — you'll know when a delivery is in flight, when it has succeeded, and how to handle failures without creating duplicate charges.

## Order Statuses

Every order moves through a defined set of statuses from creation to resolution. The table below describes each status and what it means for your integration.

| Status | Meaning |
|---|---|
| `pending` | The order has been received and is queued for processing. No delivery attempt has been made yet. |
| `processing` | The recharge is actively being delivered to the player or recipient. Do not retry the order while it is in this state. |
| `completed` | The recharge was delivered successfully. The player's account has been credited. |
| `failed` | Delivery failed. Check the `error_code` field on the order object for the specific reason. You may create a new order once you have resolved the underlying issue. |
| `refunded` | The order amount has been credited back to your API balance. This typically follows a `failed` delivery that was eligible for an automatic refund. |

## Order Object

The full order object is returned when you create an order and whenever you retrieve one. The example below shows a completed Free Fire Diamond order.

```json
{
  "id": "ord_abc123",
  "product_id": "prod_ff_100",
  "denomination_id": "denom_ff_100",
  "player_id": "123456789",
  "status": "completed",
  "created_at": "2024-01-15T10:30:00Z",
  "updated_at": "2024-01-15T10:30:45Z",
  "delivery": {
    "delivered_at": "2024-01-15T10:30:45Z",
    "confirmation_code": "FF-XYZ-789"
  },
  "error_code": null,
  "reference": "your-internal-ref-001"
}
```

<ResponseField name="id" type="string" required>
  Unique identifier for the order, generated by Smartech. Use this ID to retrieve the order or reference it in support requests.
</ResponseField>

<ResponseField name="product_id" type="string" required>
  The ID of the product that was ordered, as listed in the product catalog.
</ResponseField>

<ResponseField name="denomination_id" type="string" required>
  The ID of the specific denomination that was ordered.
</ResponseField>

<ResponseField name="player_id" type="string">
  The in-game player ID or UID supplied at order creation. Present for `PUBG_UC` and `FREE_FIRE_DIAMOND` orders. Omitted for `GIFT_CARD` orders.
</ResponseField>

<ResponseField name="status" type="string" required>
  The current status of the order. One of `pending`, `processing`, `completed`, `failed`, or `refunded`. See [Order Statuses](#order-statuses) above.
</ResponseField>

<ResponseField name="created_at" type="string" required>
  ISO 8601 timestamp for when the order was created.
</ResponseField>

<ResponseField name="updated_at" type="string" required>
  ISO 8601 timestamp for when the order was last updated. Useful for detecting status changes when polling.
</ResponseField>

<ResponseField name="delivery" type="object">
  Present when the order has reached `completed` status. Contains delivery confirmation details.

  <Expandable title="delivery object">
    <ResponseField name="delivery.delivered_at" type="string" required>
      ISO 8601 timestamp for when the recharge was successfully delivered.
    </ResponseField>

    <ResponseField name="delivery.confirmation_code" type="string" required>
      A supplier-issued confirmation code for the delivery. Retain this for dispute resolution and customer support.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="error_code" type="string | null">
  A machine-readable error code when `status` is `failed`. `null` for all other statuses. Common values include `INVALID_PLAYER_ID`, `INSUFFICIENT_BALANCE`, and `SUPPLIER_UNAVAILABLE`. See the [error reference](/guides/error-handling) for the full list.
</ResponseField>

<ResponseField name="reference" type="string">
  Your own internal reference string, if one was provided at order creation. See [Order Reference](#order-reference) below.
</ResponseField>

## Idempotency

Network failures and timeouts can leave you uncertain whether an order was actually created. To safely retry a request without risking duplicate charges, include an `Idempotency-Key` header with every order creation request.

If you send a second request with the **same `Idempotency-Key` value within 24 hours**, the API returns the original response exactly as it was — no new order is created and no additional charge is applied to your balance. After 24 hours, the key expires and a new request with the same key will create a fresh order.

Best practices for idempotency keys:
- Use a randomly generated UUID (v4) per order attempt.
- Tie the key to your own order or session ID so you can reproduce it on retry.
- Store the key alongside your order record until you confirm a terminal status.

```bash
curl --request POST \
  --url https://api.smartech-dz.com/v1/orders \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: a1b2c3d4-e5f6-7890-abcd-ef1234567890" \
  --data '{
    "product_id": "prod_ff_100",
    "denomination_id": "denom_ff_100",
    "player_id": "123456789",
    "reference": "your-internal-ref-001"
  }'
```

## Order Reference

When creating an order, you can supply an optional `reference` field containing any string that is meaningful to your system — an internal order number, a session ID, a customer identifier, or a transaction reference from your own database.

The `reference` value is stored as-is and returned on every order retrieval and webhook callback. It is not validated or processed by Smartech, and it has no effect on order routing or delivery. Its sole purpose is to make it easier for you to reconcile Smartech orders against your own records without maintaining a separate mapping table.

```json
{
  "product_id": "prod_ff_100",
  "denomination_id": "denom_ff_100",
  "player_id": "123456789",
  "reference": "ORDER-20240115-00042"
}
```

<Note>
  Once an order reaches `completed` or `refunded` status, it is **terminal** — no further status transitions will occur and the order cannot be modified or cancelled. If you need to reverse a completed transaction, contact Smartech support with the order `id` and `delivery.confirmation_code`.
</Note>
